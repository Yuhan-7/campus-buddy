# 校园搭子匹配系统 · Vue + Spring Boot + MySQL + Docker

这个目录是独立于原 Python 版的新版本。页面由 Vue 3 + Vite 构建，API 使用 Spring Boot，所有账号和需求集中保存在 MySQL，Docker Compose 启动三项服务。Redis 暂未加入：当前规则式推荐和数据量不需要缓存，避免增加单人项目的部署负担。

## 运行方式（Docker Compose）

本项目的源码复现包统一按 Docker Compose 运行，不再提供免 Docker 版本。

1. 安装并启动 Docker Desktop。
2. 将 `.env.example` 复制为 `.env`，替换其中三个密码。
3. 在本目录运行 `docker compose up --build -d`。
4. 浏览器访问 `http://localhost:8088`（或 `.env` 中指定的端口）。
5. 查看状态：`docker compose ps`；查看日志：`docker compose logs -f`；停止：`docker compose down`。

也可以在本目录运行 `sh 更新并检查网站.command`，它会重建容器并等待 `/api/health` 返回正常。网页能打开但无法登录时，先查看该健康地址；如果显示 502，说明前端已启动但后端没有运行。

`.env` 中 `DEMO_DATA=true`（默认）时，首次启动会写入演示数据，见下文“演示数据”；改为 `false` 则建立空数据库，由用户自行注册。数据库放在 Docker 卷 `mysql_data` 中，普通 `docker compose down` 不会删除数据；`docker compose down -v` 会删除数据，请勿用于日常停止。

## 两条找搭子路径

| 路径 | 适用场景 | 实现方式 |
|---|---|---|
| 需求广场主动找人 | 用户知道自己要找什么，如“羽毛球搭子” | 按关键词、类型、热门主题直接查找，**不计算相似度**，按发布时间排序 |
| 系统匹配推荐 | 用户希望系统帮忙发现合适的人 | 对自己的一条需求，按共同空闲时间、兴趣、需求标签、技能互补打分排序，并展示推荐理由 |

两条路径最终都通过“邀请 → 对方同意”达成匹配，之后双方才能查看联系方式。相似度、同义词归一只用于第二条路径。

## 功能

邮箱格式校验后注册；使用邮箱或账号 ID 登录，账号 ID 为注册日期加六位随机序列，昵称不能重复。登录后可设置 3 个密保问题，忘记密码时答对任意 2 个可重置，连续失败 5 次会暂时锁定 15 分钟。尚未设置密保问题的账号无法通过密保找回密码，应尽快登录设置。其余功能包括公开个人资料及私有联系方式、需求发布、匹配推荐、邀请处理，以及双方同意后查看联系方式。浏览器页面通过同源 `/api` 访问后端。

管理员邮箱由 `.env` 中的 `ADMIN_EMAIL` 指定。首次启动时，如果该邮箱已经注册，会把现有账号设为管理员，并将密码同步为 `.env` 中的 `ADMIN_PASSWORD`；如果尚未注册，则创建管理员账号。此初始化只执行一次，之后重启不会覆盖在网站中修改的密码。登录后在“管理端”查看最多 500 条用户、需求与匹配成功记录，可停用或恢复普通账号、撤下需求帖子、给发布者发送站内私信。管理员只查看公开资料，不查看联系方式。`.env` 不要发送给他人。

需求详情页按账号和日期记录浏览，同一账号每天打开同一帖子只计一次。需求广场显示帖子浏览量与近 7 天的热门搭子主题，主题由需求标签和标题中的“……搭子”提取；点击主题会搜索相关需求。用户可关闭、重新开放或删除自己的需求；删除会撤回待处理邀请，已同意的匹配记录仍保留。站内信在顶部“站内信”页面查看。被管理员撤下的帖子不再公开，作者也不能自行重新开放。管理员只看公开资料，通过站内信联系发布者，用户的联系方式仍只在双方同意邀请后向参与者开放。访问 `http://localhost:8088/api/health` 可检查后端是否正在运行。

## v1.2 新增（对照班级公约）

- 未登录即可浏览需求广场、需求详情与热门主题；发布、查看资料、邀请需要登录。
- 注册须同意《个人信息使用说明》（逐项列出采集的数据、用途与可见范围，`GET /api/privacy`）。
- 个人资料页可注销账号：需输入密码和“确认注销”，注销后个人资料、联系方式、密保与浏览记录被清除。
- 登录密码连续错误 5 次锁定 15 分钟。
- 关闭需求后可“撤销”；删除、拒绝、撤回、停用、撤帖等不可逆操作有二次确认。
- 顶栏“大字”“高对比”显示开关；断网提示与请求超时提示；广场分页加载。

详细对照见 `docs/班级公约落实情况.md`。

## 代码结构

```
backend/src/main/java/com/campusbuddies/
  common/      统一异常、数据库与 JSON 工具、输入校验
  auth/        注册登录、会话、密保找回、个人信息说明与注销
  profile/     个人资料
  need/        需求发布、广场、热门主题
  match/       匹配打分（MatchService 为纯函数）与推荐接口
  invitation/  邀请与联系方式交换
  admin/       管理端、站内信、启动初始化、演示数据
  ai/          智能填写与违规初筛（AiClient 接口，本地规则 / 大模型两种实现）
frontend/src/
  App.vue      页面
  api.js       请求封装（超时、离线、错误提示）
  format.js    常量与文案格式化
```

## 智能填写与违规初筛（AI 接口可选）

- **同义词归一**：匹配打分前把“打羽毛球 / 羽球 / badminton”等统一成“羽毛球”，词表在 `match/TagNormalizer.java`，不依赖 AI。
- **发布需求助手**：“发布与匹配”页输入一句话，点“智能填写”，自动填好类型、标题、标签和时间段；只填表，不发布，用户检查后自己提交。
- **违规初筛**：发布需求时检查是否疑似违规（如代写、有偿），结果只在管理端显示为提示，是否撤下由管理员决定。

两项功能都通过 `ai/AiClient` 接口实现：`.env` 中 `AI_API_URL`、`AI_API_KEY`、`AI_MODEL` 留空时使用本地规则（不联网）；三项都填写后调用 OpenAI 兼容格式的大模型接口，调用失败自动退回本地规则。发送给大模型的只有用户输入的那句话、帖子标题和说明，不含个人资料与联系方式。

## 演示数据（验收演示用）

`.env` 中 `DEMO_DATA=true`（默认即为 true）时，首次启动自动写入演示数据，之后重启不会重复写入。启动日志中出现“演示数据写入完成”即表示成功（`docker compose logs backend | grep 演示数据`）。

| 账号 | 密码 | 内容 |
|---|---|---|
| test@buddy.demo（测试同学） | test12345 | 专用测试账号：完整资料与联系方式；4 条需求（3 开放 1 关闭）；收到 2 条待处理、1 条已同意、1 条已拒绝的邀请；发出待处理、已同意、已撤回的邀请；1 条管理员站内信；已设置密保（答案：杭州 / 小橘 / 羽毛球） |
| demo01 ~ demo30@buddy.demo | demo12345 | 30 个演示用户，36 条需求，近 7 天浏览记录，约 30 条邀请；demo30 为被停用账号，另有 1 条被管理员撤下的帖子 |

演示数据中的姓名、联系方式均为虚构。数据库里已经有 `@buddy.demo` 账号时不会再写入；想重新生成，先运行 `docker compose down -v`（会删除全部数据）再启动。正式使用前请把 `DEMO_DATA` 改为 `false`。

## 功能取舍

为不增加用户负担或部署负担，以下功能有意不做：注册邮箱验证码、Redis 缓存、站内即时聊天、手机号实名。

## 与旧版数据

此版本使用全新 MySQL 数据库，不会自动读取原 Python 版的 `data.sqlite3`。不要把原数据库放进公开仓库或镜像。需要保留旧账号时，应另做一次性迁移并处理密码哈希算法差异。

## 公开部署前

当前配置用于本机或可信网络演示。若向互联网开放，需要域名和 HTTPS 反向代理、邮箱所有权验证、按 IP 的注册限流（目前只有按账号的登录失败锁定）、备份与恢复流程，并检查网络与服务器访问控制。不要把 8088 的 HTTP 服务直接暴露到公网。注册邮箱目前只是账号名，不发送验证邮件，也不能证明是本校学生。
