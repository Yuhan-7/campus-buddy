# 代码审查记录（v1.0 → v1.4）

审查对象：v1.0 初始代码（后端单个 `ApiController`，前端单个 `App.vue`）及之后各轮修改。
审查依据：① 班级软件开发行为公约逐条对照；② 设计原则（模块化、低耦合、信息隐藏、单一职责）；③ 安全与隐私检查清单；④ 测试与实际使用中暴露的问题。

## 一、发现并修正的缺陷

| 编号 | 问题 | 发现方式 | 影响 | 处理 |
|---|---|---|---|---|
| D1 | 需求广场先 `LIMIT 200` 取出数据，再在内存中按类型、关键词筛选 | 阅读代码 | 数据超过 200 条时，符合条件的需求会漏掉 | 改为数据库内筛选后分页（每页 24 条），关键词中的 % _ 按字面匹配 |
| D2 | 开始时间较晚时按时长计算会得到 24:00 以后的结束时间（如 25:00） | 阅读代码 | 后端拒绝但提示不清，用户不知道哪里填错 | 前端提交前校验并给出明确提示 |
| D3 | 推荐接口对每个候选人单独查询一次其需求（N+1 查询） | 阅读代码 | 用户多时推荐变慢 | 一次查出所有开放需求，按用户分组后打分 |
| D4 | 顶栏“登录 / 注册”按钮文字颜色被通用样式覆盖 | 运行检查 | 按钮文字几乎看不清 | 修正样式优先级 |
| D5 | 联系方式点开后无法收起 | 使用测试 | 体验不一致 | 改为“查看 / 收起”切换，同时补“清除筛选” |
| D6 | 智能填写不识别“一到三点”等中文数字时间 | 使用测试 | 填出错误时段 | 先把中文数字转为阿拉伯数字再识别，并补充测试 |

## 三、结构与可维护性问题（已重构）

| 编号 | 问题 | 处理 | 对应原则 |
|---|---|---|---|
| S1 | 后端全部逻辑在一个 113 行、单行最长约 2000 字符的控制器中 | 按职责拆为 common / auth / profile / need / match / invitation / admin / ai 八个包 | 模块化、高内聚低耦合 |
| S2 | 匹配打分与数据库查询混在一起，无法单独测试 | 抽为不访问数据库的 `MatchService` | 单一职责、可测试性 |
| S3 | 各处分别拼装错误响应 | 统一由 `ApiExceptionHandler` 处理 | 关注点分离 |
| S4 | 前端请求、常量、文案散落在页面中 | 拆出 `api.js`、`format.js` | 模块化 |
| S5 | 仓库中的前端构建产物与新接口不兼容 | 删除，统一按 Docker Compose 构建运行 | 配置一致性 |

## 四、审查确认无需修改的部分

- 所有 SQL 均使用参数占位符，未发现拼接用户输入，可防 SQL 注入。
- 密码与密保答案使用 BCrypt 存储；登录凭证 Cookie 设置 HttpOnly、SameSite=Strict，数据库只存其哈希。
- 写操作校验请求来源（Origin 与 Host 一致），防跨站请求伪造。
- 邀请状态更新已限定原状态为 pending，可避免重复接受或拒绝。
- 登录失败提示不区分“账号不存在”与“密码错误”。
