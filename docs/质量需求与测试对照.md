# 质量需求与测试用例对照

运行全部测试：`cd backend && mvn test`（需要 Java 21 与 Maven，测试使用内存 H2 数据库，不需要 MySQL）。

测试用例的 `@DisplayName` 以下表编号开头，可直接在测试报告中对应。

## 质量需求

| 编号 | 类别 | 质量需求（可验证的表述） | 测试用例 |
|---|---|---|---|
| QR-P1 | 隐私 | 未勾选同意《个人信息使用说明》的注册请求返回 400；说明清单无需登录即可获取 | `QualityRequirementTest.registrationRequiresPrivacyConsent` |
| QR-P2 | 隐私 | 注销账号须同时提供正确密码和确认词；注销后旧会话失效、无法登录、公开资料与联系方式为空、待处理邀请变为已撤回 | `QualityRequirementTest.accountDeletionErasesPersonalData` |
| QR-U1 | 易用性 | 未登录可浏览广场、详情、热门主题；未登录发布、邀请、查看个人资料返回 401 | `QualityRequirementTest.guestCanBrowseButNotWrite` |
| QR-S1 | 安全 | 同一账号密码连续错误 5 次后返回 429 并锁定 15 分钟，锁定期间正确密码也不能登录；未锁定时不存在的账号与密码错误提示相同 | `QualityRequirementTest.loginLocksAfterRepeatedFailures` |
| QR-S2 | 安全 | 来源（Origin）与 Host 不一致的写请求返回 403 | `QualityRequirementTest.crossOriginWriteRejected` |
| QR-F1 | 功能正确性 | 广场按类型与关键词在数据库中筛选后分页；关键词中的 `%` 不作为通配符 | `QualityRequirementTest.plazaFiltersInDatabase` |
| QR-F2 | 可恢复性 | 关闭的需求可重新开放；删除后的需求不能再修改状态 | `QualityRequirementTest.closeIsUndoableDeleteIsFinal` |
| QR-F3 | 功能正确性 | 未填写任何联系方式时不能发出邀请 | `QualityRequirementTest.inviteRequiresContact` |
| QR-F4 | 功能正确性 | 拒绝邀请可附原因（最多 100 字，超长返回 400），发送方能在邀请列表看到原因 | `QualityRequirementTest.rejectWithReason` |
| QR-M1 ~ M4 | 功能正确性 | 匹配打分公式：无共同时间不推荐；满足全部条件得 100 分；共同空闲 1 小时得 15 分；技能互补双向计算 | `MatchServiceTest` 4 个用例 |
| QR-M5 | 功能正确性 | 同一兴趣的不同说法（打羽毛球 / 羽球 / badminton）归一后能互相匹配 | `AiAssistTest.synonymsMatch` |
| QR-A1 ~ A3 | 易用性 / 内容安全 | 智能填写能从一句话拆出类型、标签、星期、时间段，识别不出的字段留空；含“代写”等敏感词的帖子被标记疑似违规 | `AiAssistTest` 3 个用例 |
| QR-A4 | 安全 / 内容安全 | 智能填写需要登录；发布含敏感词的帖子后，管理端能看到“疑似违规”提示 | `QualityRequirementTest.aiDraftAndModerationNote` |
| QR-R1 | 容错 | 数据库中格式错误的时间段不会导致推荐接口报错 | `MatchServiceTest.malformedSlotsIgnored` |
| QR-R2 ~ R5 | 容错 / 输入校验 | 邮箱格式、时间段、标签、搜索通配符的校验 | `InputsTest` 4 个用例 |

## 其他测试（功能流程）

`ApiFlowTest` 4 个用例覆盖：注册与管理员权限、浏览量去重与管理员撤帖/私信、账号 ID 登录与密保找回、邀请同意后才能查看联系方式。

## 前端无自动化测试的部分（手工检查项）

无障碍与弱网相关需求目前靠手工检查：开启“大字”后页面放大约 20%；开启“高对比”后正文为纯黑；断开网络后出现顶部提示、操作提示“当前处于离线状态”；关闭需求后 8 秒内可点“撤销”。
